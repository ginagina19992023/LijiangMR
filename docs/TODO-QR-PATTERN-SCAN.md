# 代办 · 扫码出纹样绘制（博物馆现场用的小功能）

> 来源：2026-09-05 微信群「漓江回声 mr 版」讨论，与 kk、西西里浓缩咖啡。
> 状态：**②入场动画已实现**(四套,用现有素材,无新增美术);扫码本身未做。
> 这不是 9.1 需求里的条目,是额外加的小功能。

---

## 1. 要做什么

在博物馆现场，**文物旁边摆一张打印的二维码**，玩家戴着头显扫它。

## 整体是三段（2026-09-06 定，以此为准）

```
① 扫到二维码
     二维码位置浮现一个光圈（用打击那个光环）

② 【入场动画 · 3~5 秒】  ← 全新,四个纹样各一套,是本功能主要工作量
     该纹样的生物从二维码里出来,在光圈周围活动
     每种按自己的习性演,不是同一个模板改参数

③ 入场动画散去 → 进入打击环节  ← 战斗里已经有,拉出来跑一遍即可
     按各自的音符类型飞入、判定、命中,配一行文字提示
```

> ⚠️ **②和③是两段不同的东西,别混。**
> ③里的"飞入动画"(青蛙上跳、双翼汇合、左右分边)是**音符飞向判定点**的过程,战斗里早就有;
> ②是打击开始**之前**的一段独立演出 —— 现已实现,见 Assets/Scripts/Stages/LijiangEchoPatternIntro.cs。

> ⚠️ 这也和**最初**写的「浮现纹样 → 点击 → 进入描绘」不是同一套。
> 现在是**打击**(圆环 + 挥击判定 + 音效),不是**描绘**(沿着线描)。

---

## 二维码用哪几个纹样：定为四个

**四个二维码，各对一种音符打法。铜钱纹不做**（它没有对应的打击音符，第③段教学无从教起）。

### 逐个纹样

| 码 | 纹样 | ② 入场动画（3~5s，全新） | ③ 打击环节 | 提示文字 | ③ 的代码现状 |
|---|---|---|---|---|---|
| A | **鱼纹** | ✅ **已定**：鱼从光圈外面跃起、跳进光圈里；另有鱼从光圈旁探出头，头旁泛起涟漪（同款光圈但更小的白圈）；探头停留一小会儿后也纷纷跃入光圈 | 左边飞来用左手打、右边飞来用右手打 | 左右手提示 | ✅ 已有（左右手判定 + 按方向自动镜像） |
| B | **蛇纹** | ✅ **已定**：先响起「嘶嘶」声 → 一条蛇扭动着身子从旁边过来 → **缠上光圈** → 顺时针沿光圈转一圈 → 消失 | 按住时颜色从紫渐变到金，金了即满 | 「按住不放」 | ✅ 已有（`:3651`） |
| C | **蛙纹** | ✅ **已定**：把光圈**当作一片荷叶**（贴图不换）。青蛙自画面下方跳上圈外的小荷叶、叫几声 → 跳进中间大光圈 → 左右转动张望 → 前方渐显下一片荷叶，跳过去 → 再跳出画面外 | 从下方蓄势升到圆心，过判定点后抛物线跃出 | 「滑动手柄」 | ✅ 已有（`:3184`） |
| D | **鸟纹** | **几只鸟扇着翅膀从二维码飞出，围光圈盘旋，忽远忽近**（已描述） | 左右各飞来一只翅膀，圆心叠合成整鸟 | 「双击」 | ✅ 已有（`:2965`） |

> **注意：不是四个都"绕光圈盘旋"。** 盘旋是鸟的动作；鱼是跃入、探头。
> 每种生物按自己的习性演，别套同一个模板。

#### 鱼纹入场动画（细节）

- 鱼从**光圈外侧跃起**，划一道弧线**跳进光圈里**
- 另有鱼从**光圈旁边探出头**，头旁泛起**涟漪** —— 和主光圈同款、但更小的白色圆环
- 探头的鱼停留一小会儿，随后也**纷纷跃入光圈**
- 整体是"鱼群跳水"的意象，不是绕圈飞

> 涟漪那个小白圈可以直接复用主光圈的贴图（`battle/hit_ring_center`）缩小 + 降透明度，
> 不用另做美术。

#### 蛇纹入场动画（细节）

1. 先响起 **「嘶嘶」声**（音效先于画面）
2. 一条蛇**扭动着身子从旁边过来**
3. **缠上光圈**
4. 顺着光圈**顺时针转一圈**
5. 消失 → 进入打击环节

#### 蛙纹入场动画（细节）

**光圈只是「概念上」是一片荷叶 —— 不要把贴图换成荷叶。** 圈外另起一个小光圈当"小荷叶"。

1. 小荷叶浮现，青蛙从**画面下方**跳上去
2. 蹲在小荷叶上，**叫几声**
3. 跳进**中间的大光圈**（主荷叶）
4. 在上面**左右转动几下**张望
5. 前方**渐显出下一片荷叶**，青蛙跳过去
6. 再从那片荷叶**跳出画面外**

#### 鸟纹入场动画（细节）

几只鸟扇着翅膀从二维码里飞出来，**围着光圈盘旋**，忽远忽近（有深度变化，不是平面转圈）。

> ⚠️ 别把②③混为一谈：③里那些"飞入动画"（青蛙上跳、双翼汇合、左右分边）是**音符飞向判定点**的过程，
> 战斗里早就有;②是打击开始**之前**的一段独立演出,现已实现。

对应关系取自代码，不是猜的：`LijiangEchoGameController:3380`（音符类型 → 纹样 Prefab）。

### 这么定顺带解决了之前两处对不上

- 9-05 微信里说的是「铜钱纹 / **鹰纹** / 蛇纹」，9-06 补充玩法时说的是「蛙纹 / 鸟纹 / 鱼纹」。
  两次指的其实是不同的东西（见下），现在统一按上表的四个走。
- **「鹰纹」就是「鸟纹」**（队友说过"鸟纹就是采取的这个鼓上面的纹样"），只是叫法不同。

### 别再混淆：游戏里有三组"三个纹样"，指的不是同一批

| 哪一组 | 内容 | 由什么决定 |
|---|---|---|
| **选关的三关** | 蛙纹 / 鸟纹 / 鱼纹 | 玩家点哪个（当前只开放蛙纹） |
| **行进段描绘的三次** | 蛇纹 / 鸟纹 / 铜钱 | **第几次绘制**，固定顺序，与选哪一关无关 |
| **本功能的二维码** | 鱼 / 蛇 / 蛙 / 鸟（四个） | 扫到哪个码 |

9-05 那次说「铜钱/鹰/蛇」，是照着**描绘的三个**讲的；9-06 说「蛙/鸟/鱼」，是照着**选关的三关**讲的。
两边都没说错，只是指的不是同一组。本功能自己用第三组，四个。

**四套入场动画已全部设计完并实现**(见 Assets/Scripts/Stages/LijiangEchoPatternIntro.cs)。
第③段和按住时的表现都不用再设计,战斗里已经有了。

剩下没做的是扫码本身:摄像头取帧、二维码解码、世界锚定。

## 2. 已经定下来的

| 项 | 结论 |
|---|---|
| 用什么触发 | **先做二维码**。视觉识别（直接认文物）作为后续优化 |
| 几个码 | **四个**，各对应一种音符打法（详见下节）。**铜钱纹不做** —— 它没有对应的打击音符 |
| 对应关系 | 鱼纹=单击 / 蛇纹=长按 / 蛙纹=挥划 / 鸟纹=双击 |
| 二维码谁做 | **我们自己造、自己打印、自己带过去贴在文物旁**。不依赖博物馆，内容格式我们说了算，测试用哪张就打哪张 |
| 纹样素材 | **不用队友再传**，Unity 工程里已有；尺寸不合适自己裁或程序裁 |

**为什么不是"扫一个鼓出几个纹样"**：一开始想的是扫铜鼓、空中飘出几个纹样让玩家挑一个。kk 说这些纹样其实来自不同文物（鼓上只有鸟纹），所以改成一个码对一个纹样，更准确也更好实现。

## 4. 技术可行性：已确认可做

Quest 3/3S 上应用**能不能拿到摄像头画面**是这个功能的生死线——早期 Horizon OS 是完全禁止的，扫码根本无从谈起。本工程已经具备条件：

| 前提 | 现状 |
|---|---|
| Meta XR SDK 版本 | `com.meta.xr.sdk.all` **201.0.0**（远高于开放摄像头的 v74） |
| Passthrough Camera API | ✅ 已随 MR Utility Kit 提供：`PassthroughCameraAccess.cs` |
| 摄像头权限 | ✅ AndroidManifest 里已有 `horizonos.permission.HEADSET_CAMERA` |
| Passthrough 功能 | ✅ 已声明 `com.oculus.feature.PASSTHROUGH` |
| 目标设备 | Quest 3 / 3S（`targetDeviceTypes` 已含），**Quest 2 没有彩色透视摄像头，做不了** |

> ⚠️ Quest 2 用户扫不了码，功能要做优雅降级（提示"本设备不支持"或退回手动选纹样）。

### 大致做法（按「盘旋 + 打击」这套）

1. `PassthroughCameraAccess` 取摄像头帧（`WebCamTexture` 形式）
2. 解码二维码 —— 需要引入解码库（ZXing.Net，MIT 协议；工程里目前**没有**，要新加）
3. 解出标识串 → 纹样序号 0/1/2，并拿到二维码在空间中的位置
4. 在二维码位置生成**中心光圈**
5. 纹样从二维码里飞出，**绕着光圈盘旋**，深度时远时近
6. 检测手柄**打击光圈** → 光圈中央浮现纹样 + 播对应音效

### 哪些能直接复用

| 要素 | 现成的东西 |
|---|---|
| 中心光圈贴图 | `battle/hit_ring_center` |
| 光圈 Prefab 钩子 | `Ring_Center`（**目前不存在**，跑一次「2 美术Prefab/圆环与手/生成默认圆环 Prefab」就有） |
| 光圈命中反馈 | `LijiangEchoRingFeedback`（基类）+ `LijiangEchoRingHitFlash`（示例实现） |
| 打击判定 | 战斗那套：`BattleStrikePressed` / `IsDeliberateBattleSwing`，含左右手判定与蛙纹放宽 |
| 命中音效 | `PlaySfx("snake" / "swipe" / "hit" / "button" ...)`，蛇/蛙/鱼各有一条 |
| 纹样贴图 + 裁剪框 | `TraceStageController.TryGetPatternArt(序号)` —— 已经开放成 public static |
| 飞入 + 深度变化 | `IntroStageController.FlyItem` 那套（起点终点插值 + 深度 + 淡入），可参考 |

### 需要新写的

## 6. 扫码已实现(2026-09-06)——但做法和上面第 4 节估的不一样

**上面第 4 节写的「摄像头取帧 + 引入 ZXing 解码 + 自己反算二维码空间位置」那条路,没有走。**
翻 Meta XR SDK 201 的时候发现这件事系统已经做完了:MRUK 提供**系统级的二维码追踪**,
直接给出【解码后的字符串】和【一个持续跟踪的世界锚点】。

所以最终:
- ❌ 不引入 ZXing(不新增第三方依赖)
- ❌ 不自己取摄像头帧、不自己写解码
- ❌ 不用按二维码像素大小反算距离
- ✅ 锚定精度和稳定性由系统负责,玩家走动时演出留在原地

用到的 API(都在 `Assets/Scripts/Stages/LijiangEchoQrScan.cs` 里):

| 用途 | API |
|---|---|
| 设备支不支持 | `MRUK.Instance.QRCodeTrackingSupported`(Quest 2 为 false) |
| 打开追踪 | `SceneSettings.TrackerConfiguration.QRCodeTrackingEnabled = true` ⚠️ 是 struct,要取出改完塞回去 |
| 认出来了 | `SceneSettings.TrackableAdded` → `MRUKTrackable` |
| 二维码内容 | `MRUKTrackable.MarkerPayloadString` |
| 世界位姿 | `MRUKTrackable.transform`(挂成子物体即可自动跟随) |
| 二维码实际边长 | `MRUKTrackable.PlaneRect` —— 用它把演出缩放到现场尺度 |

权限 `com.oculus.permission.USE_SCENE` 和 `USE_ANCHOR_API` 工程里**早就声明过了**,没动 manifest。

## 7. ③打击环节已实现(2026-09-06)

原来这里是占位(提示打法 → 随便按一下 → 出音效 → 结束)。现在是**四种真打法**,
见 `Assets/Scripts/Stages/LijiangEchoPatternStrike.cs`。

| 纹样 | 打法 | 表现 | 判定 |
|---|---|---|---|
| 鱼纹 | 单击 | 左右交替飞向光圈 | **飞哪边就得用哪只手**,错手不算 |
| 蛇纹 | 长按 | 光圈从紫渐变到金 | 按住读条,金了即满;松手会回落(不清零) |
| 蛙纹 | 挥划 | 从下方蓄势升到圆心 | **向上挑**;判定窗口按 1.6 倍放宽 |
| 鸟纹 | 双击 | 左右各飞来一只,圆心叠合 | **两只手同时**,允许在同步窗口内一前一后 |

命中后光圈中央浮现对应纹样并播音效,和需求一致。

**为什么没有直接调战斗那套**:战斗判定锁在 `LijiangEchoGameController` 那 5800 行里,
拆出来是 `REFACTOR-STEP2-BATTLE-SPLIT.md` 的活。这里按同样的规则单独实现一份,
**阈值全部对齐战斗的取值**(hitWindowSeconds / swipeWindowScale / swipeMinimumSpeed /
swipeUpwardSpeed / twoHandSyncWindow),拆分完成后可以整体换掉。

PC 兜底也和战斗、描绘完全一致,三处规则不打架:

```
鼠标左键 = 右手     Shift + 左键 = 左手
空格 / 回车 = 双手   ↑ 键 = 向上挥
```

### 鸟纹的「两翼汇合」怎么做的(照搬战斗)

一开始以为要单翅素材才能做「两只翅膀从两边飞来汇合成整鸟」。翻战斗那边发现
根本不需要新美术 —— `LijiangEchoGameController:3017` 的做法是:

- **同一只鸟纹**,原体固定从**右**侧飞入(= 右翼)
- 再生成一只 `localScale.x` 取负的**水平镜像分身**,从**左**侧飞入(= 左翼)
- 分身位置永远取本体的 `x` 取反,透明度同步 → 两只对称汇合到圆心拼成整鸟
- 分身**纯视觉,不参与判定**

打击这边现在完全照这个来(`LijiangEchoPatternStrike.SyncMirrorTwin`),
所以不需要找美术要单翅素材。
