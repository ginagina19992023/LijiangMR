# 代办 · 扫码出纹样绘制（博物馆现场用的小功能）

> 来源：2026-09-05 微信群「漓江回声 mr 版」讨论，与 kk、西西里浓缩咖啡。
> 状态：**未开工**。这不是 9.1 需求里的条目，是额外加的小功能。

---

## 1. 要做什么

在博物馆现场，**文物旁边摆一张打印的二维码**；玩家戴着头显扫它 → **空中浮现对应的纹样 → 点击进入绘制**。

一句话：把游戏里已有的「浮现纹样 → 点击 → 描绘」那套，从关卡流程里摘出来，改由扫二维码触发。

## 2. 已经定下来的

| 项 | 结论 |
|---|---|
| 用什么触发 | **先做二维码**。视觉识别（直接认文物）作为后续优化 |
| 几个码 | **三个**，各对应一个纹样 |
| 对应关系 | 二维码 A → **铜钱纹**；B → **鹰纹**；C → **蛇纹** |
| 二维码谁做 | kk 那边打印，摆到博物馆文物旁 |
| 纹样素材 | **不用队友再传**，Unity 工程里已有；尺寸不合适自己裁或程序裁 |

**为什么不是"扫一个鼓出三个纹样"**：一开始想的是扫铜鼓、空中飘出三个纹样让玩家挑一个。kk 说三个纹样其实来自不同文物（鼓上只有鸟纹），所以改成三个码各对一个纹样，更准确也更好实现。

## 3. 待确认（开工前问清楚）

1. **「鹰纹」和游戏里的「鸟纹」是不是同一个？**
   kk 说过"鸟纹就是采取的这个鼓上面的纹样"，但列对应关系时写的是"鹰纹"。
   游戏里 `TraceStageController.tracePaths` 是 `snake_trace / bird_trace / coin_trace`（蛇/鸟/铜钱），
   刚好能对上"蛇纹/鹰纹/铜钱纹"——但名字要跟队友核一次，别做错。
2. **二维码里放什么内容？** 建议放一个短标识串（如 `lijiang://pattern/coin`），不要放网址，
   避免头显里被系统浏览器截走。
3. **扫完之后的完整流程**：只绘制一次就结束？还是绘制完显示对应的纹样解析卡面（复用现有 15 张卡面）？
4. **在哪个入口进入**：新开一个「博物馆模式」场景，还是在开始界面加一个入口？

## 4. 技术可行性：已确认可做

Quest 3/3S 上应用**能不能拿到摄像头画面**是这个功能的生死线——早期 Horizon OS 是完全禁止的，扫码根本无从谈起。本工程已经具备条件：

| 前提 | 现状 |
|---|---|
| Meta XR SDK 版本 | `com.meta.xr.sdk.all` **201.0.0**（远高于开放摄像头的 v74） |
| Passthrough Camera API | ✅ 已随 MR Utility Kit 提供：`PassthroughCameraAccess.cs` |
| 摄像头权限 | ✅ AndroidManifest 里已有 `horizonos.permission.HEADSET_CAMERA` |
| Passthrough 功能 | ✅ 已声明 `com.oculus.feature.PASSTHROUGH` |
| 目标设备 | Quest 3 / 3S（`targetDeviceTypes` 已含），**Quest 2 没有彩色透视摄像头，做不了** |

> ⚠️ Quest 2 用户扫不了码，功能要做优雅降级（提示"本设备不支持"或退回手动选纹样）。

### 大致做法

1. `PassthroughCameraAccess` 取摄像头帧（`WebCamTexture` 形式）
2. 解码二维码 —— 需要引入一个解码库（ZXing.Net 常用，MIT 协议；工程里目前**没有**，要新加）
3. 解出标识串 → 映射到纹样序号 0/1/2
4. 在玩家面前生成浮动纹样（**直接复用** `IntroStageController.AddGateGlyphFly` 那套飘来停住的效果）
5. 点击 → `TraceStageController.Begin(纹样序号, 双手?, 画完回调)`

**好消息是第 4、5 步几乎不用新写**：描绘早就被重构成了可重入模块（`Begin/Teardown`），
拉起一次描绘只要一行，不依赖任何关卡流程。这正是当初拆成模块的收益。

### 工作量粗估

| 部分 | 估计 |
|---|---|
| 摄像头取帧 + ZXing 解码 | 半天～一天（含真机调试，扫码识别率要现场试） |
| 纹样浮现 + 绘制串接 | 小半天（复用现成模块） |
| 新场景 / 入口 / 降级处理 | 小半天 |
