# 代办 · 扫码出纹样绘制（博物馆现场用的小功能）

> 来源：2026-09-05 微信群「漓江回声 mr 版」讨论，与 kk、西西里浓缩咖啡。
> 状态：**未开工**。这不是 9.1 需求里的条目，是额外加的小功能。

---

## 1. 要做什么

在博物馆现场，**文物旁边摆一张打印的二维码**，玩家戴着头显扫它。

### 交互设想（2026-09-06 补充，以此为准）

1. 扫到码 → 对应的纹样**从二维码里缓缓飞出来**
2. 纹样**围绕二维码盘旋**（鸟纹就像鸟一样绕着飞），中心是一个**光圈**
3. 盘旋时**时远时近**，有深度变化，不是平面转圈
4. 玩家用**手柄打击那个光圈**
5. 命中 → 光圈中央**浮现该纹样** + **播放对应的音效**

### 第二段：接上战斗玩法教学（2026-09-06 再补充）

打击光圈、纹样浮现之后，**周围盘旋的图案消失**，转成一次**正常的打击音符**，
让玩家在这里学会这一种音符的打法。屏幕上给一行文字提示。

| 纹样 | 音符类型 | 表现 | 文字提示 |
|---|---|---|---|
| **蛙纹** | 挥划（Swipe） | 青蛙从下方跳上来、再跳出去 | 「滑动手柄」 |
| **鸟纹** | 双击（Double） | 两只鸟的翅膀从左右两边各飞过来汇合 | 「双击」 |
| **鱼纹** | 单击（Strike） | 左边飞来的用左手打、右边飞来的用右手打 | 左右手提示 |

> ⚠️ 这和最初写的「浮现纹样 → 点击 → 进入描绘」**不是同一套交互**。
> 现在是**打击**（战斗那套：圆环 + 挥击判定 + 音效），不是**描绘**（沿着线描）。
> 下面的技术映射已按新版重写。

---

## ⚠️ 必须先解决的矛盾：到底是哪三个纹样

**两次说的三个纹样对不上，照现在的记录去印二维码一定会印错。**

| 出处 | 三个纹样 |
|---|---|
| 9-05 微信里定的二维码对应 | **铜钱纹 / 鹰纹 / 蛇纹** |
| 9-06 补充的玩法教学 | **蛙纹 / 鸟纹 / 鱼纹** |

代码里的权威对应（`LijiangEchoGameController:3380`、`TraceStageController:22`、`SelectStageController:13`）：

| 纹样 | 音符类型 | 音符 Prefab | 是描绘用的吗 | 是选关的关卡吗 |
|---|---|---|---|---|
| **鱼纹** | 单击 Strike | `Note_Fish` | ✘ | ✔（第三关） |
| **蛇纹** | 长按 Hold | `Note_Snake` | ✔ | ✘ |
| **蛙纹** | 挥划 Swipe | `Note_Frog` | ✘ | ✔（第一关，唯一开放的） |
| **鸟纹** | 双击 Double | `Note_Bird` | ✔ | ✔（第二关） |
| **铜钱纹** | — 没有对应音符 | — | ✔ | ✘ |

由此可以看出：

- **「鹰纹」大概率就是「鸟纹」**（队友说过"鸟纹就是采取的这个鼓上面的纹样"），只是叫法不同。
- **铜钱纹没有对应的打击音符**，所以如果二维码用「铜钱纹」，第二段的玩法教学就没得教。
- 想教「滑动/双击/左右手」这三种打法，对应的纹样应该是 **蛙纹 / 鸟纹 / 鱼纹**，
  而不是 9-05 定的那三个。

**建议**：二维码改成 **蛙纹 / 鸟纹 / 鱼纹** 三个 —— 既能教三种打法，又正好是选关界面的三关，
故事上也说得通（扫到哪个纹样，就预习哪一关）。定下来之前不要印码。

## 2. 已经定下来的

| 项 | 结论 |
|---|---|
| 用什么触发 | **先做二维码**。视觉识别（直接认文物）作为后续优化 |
| 几个码 | **三个**，各对应一个纹样 |
| 对应关系 | 二维码 A → **铜钱纹**；B → **鹰纹**；C → **蛇纹** |
| 二维码谁做 | **我们自己造、自己打印、自己带过去贴在文物旁**。不依赖博物馆，内容格式我们说了算，测试用哪张就打哪张 |
| 纹样素材 | **不用队友再传**，Unity 工程里已有；尺寸不合适自己裁或程序裁 |

**为什么不是"扫一个鼓出三个纹样"**：一开始想的是扫铜鼓、空中飘出三个纹样让玩家挑一个。kk 说三个纹样其实来自不同文物（鼓上只有鸟纹），所以改成三个码各对一个纹样，更准确也更好实现。

## 3. 待确认（开工前问清楚）

## 4. 技术可行性：已确认可做

Quest 3/3S 上应用**能不能拿到摄像头画面**是这个功能的生死线——早期 Horizon OS 是完全禁止的，扫码根本无从谈起。本工程已经具备条件：

| 前提 | 现状 |
|---|---|
| Meta XR SDK 版本 | `com.meta.xr.sdk.all` **201.0.0**（远高于开放摄像头的 v74） |
| Passthrough Camera API | ✅ 已随 MR Utility Kit 提供：`PassthroughCameraAccess.cs` |
| 摄像头权限 | ✅ AndroidManifest 里已有 `horizonos.permission.HEADSET_CAMERA` |
| Passthrough 功能 | ✅ 已声明 `com.oculus.feature.PASSTHROUGH` |
| 目标设备 | Quest 3 / 3S（`targetDeviceTypes` 已含），**Quest 2 没有彩色透视摄像头，做不了** |

> ⚠️ Quest 2 用户扫不了码，功能要做优雅降级（提示"本设备不支持"或退回手动选纹样）。

### 大致做法（按「盘旋 + 打击」这套）

1. `PassthroughCameraAccess` 取摄像头帧（`WebCamTexture` 形式）
2. 解码二维码 —— 需要引入解码库（ZXing.Net，MIT 协议；工程里目前**没有**，要新加）
3. 解出标识串 → 纹样序号 0/1/2，并拿到二维码在空间中的位置
4. 在二维码位置生成**中心光圈**
5. 纹样从二维码里飞出，**绕着光圈盘旋**，深度时远时近
6. 检测手柄**打击光圈** → 光圈中央浮现纹样 + 播对应音效

### 哪些能直接复用

| 要素 | 现成的东西 |
|---|---|
| 中心光圈贴图 | `battle/hit_ring_center` |
| 光圈 Prefab 钩子 | `Ring_Center`（**目前不存在**，跑一次「2 美术Prefab/圆环与手/生成默认圆环 Prefab」就有） |
| 光圈命中反馈 | `LijiangEchoRingFeedback`（基类）+ `LijiangEchoRingHitFlash`（示例实现） |
| 打击判定 | 战斗那套：`BattleStrikePressed` / `IsDeliberateBattleSwing`，含左右手判定与蛙纹放宽 |
| 命中音效 | `PlaySfx("snake" / "swipe" / "hit" / "button" ...)`，蛇/蛙/鱼各有一条 |
| 纹样贴图 + 裁剪框 | `TraceStageController.TryGetPatternArt(序号)` —— 已经开放成 public static |
| 飞入 + 深度变化 | `IntroStageController.FlyItem` 那套（起点终点插值 + 深度 + 淡入），可参考 |

### 需要新写的

- **盘旋运动**：现有 `LijiangEchoStageKit.MotionKind` 只有 `FloatY / FloatX / Pulse / Flame / Monster / Wing / Hand`，
  **没有绕圈**。要加一个 `Orbit`：半径 + 角速度 + 深度起伏（`sin/cos` 就够，不复杂）。
- **世界锚定**：以上都是「贴在玩家面前的舞台平面」的做法，而这个功能要**贴在二维码所在的真实位置**上。
  需要把光圈和盘旋中心锚到二维码的空间坐标，玩家走动时它留在原地。
- 摄像头取帧 + 解码本身。

### 工作量粗估

| 部分 | 估计 |
|---|---|
| 摄像头取帧 + ZXing 解码 | 半天～一天（含真机调试，识别率要现场试） |
| 世界锚定 + 盘旋运动 | 半天（盘旋不难，锚定要调） |
| 光圈 + 打击 + 音效串接 | 小半天（复用战斗现成的） |
| 新场景 / 入口 / Quest 2 降级 | 小半天 |
