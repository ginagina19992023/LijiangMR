## 1. 分支模型

> **本节已于 2026-09-06 更新**,替代原来"main 是冻结基线、两条历史不相干、靠强推同步"的说法 —— 那个描述现在是错的,别再照着做。

| 分支 | 作用 | 谁动它 |
|---|---|---|
| **`main`** | **最终分支**,也是**队友验收跑测**用的那条。想看/跑当前成品,checkout 它。 | 开发分支验过之后同步上来。**不在 main 上直接改。** |
| **`battle-*`**(当前是 `battle-visual-hands`) | **开发分支**,日常改动都在这。以后新开的开发分支也用 `battle-` 开头。 | 所有日常提交。 |

**怎么同步到 main**

`main` 现在是 `battle-visual-hands` 的祖先,所以是**快进(fast-forward)**,不是强推、也不用 merge:

```bash
git push origin battle-visual-hands:main
```

推之前先确认一下能快进(能的话不会丢任何提交):

```bash
git merge-base --is-ancestor origin/main origin/battle-visual-hands && echo "可以快进"
git rev-list --count origin/battle-visual-hands..origin/main   # 应为 0,即 main 上没有独有提交
```

**队友那边**:`main` 是快进的,普通 `git pull` 就行,不需要 reset,也不会遇到历史冲突。

- 旧内容/退役分支都打了 `archive/*` 标签,想找回随时 `git checkout archive/<名字>`:
  `archive/main-old-2d6e380`、`archive/refactor-scene-split`、`archive/stage-start-authoring`、`archive/spec-chart-b`。

> **场景拆分为什么能和实机同分支并存不打架**:所有拆分代码都被 `Application.CanStreamedLevelBeLoaded("Stage_Xxx")` 守卫——**场景没加进 Build Settings 之前,这些代码一律休眠,走的还是旧流程**,不会破坏实机。

场景拆分顺序:**过场 Stage_Intro → 描绘 Stage_Trace →(以后)战斗**。运行时链路:
`选关 → Stage_Intro(悬浮+入关视频)→ Stage_Trace(描绘)→ 旧主场景[战斗] → 结算`。

代码全部就绪且带守卫,接流程不用你手接。你只需建场景 + 挂控制器 + 进 Build Settings。

### Step 1 — 建 `Stage_Intro`
1. 复制 `Assets/Scenes/Stages/Stage_Select.unity` → 改名 **`Stage_Intro.unity`**。
2. 根物件上**删** `SelectStageController` 组件,**挂** `IntroStageController`。XR Rig / 相机原样别动。
3. Build Settings 把 `Stage_Intro` 放到 **`Stage_Select` 之后**。
4. 确认 `Assets/StreamingAssets/LijiangEchoVideos/pre_level.mp4` 是真文件。
- **验**:选关 → 悬浮过场(**推摇杆/键盘 W↑ 才往前走,松开停;远山不动**)→ 走到头切纯黑视频(完整播完)→ 描绘 → 战斗。
- 组件上有 `Intro Manual Walk` 勾选框:取消勾选即回到"自动按时间走"。

### Step 2 — 建 `Stage_Trace`
1. 复制 `Stage_Select.unity` → 改名 **`Stage_Trace.unity`**。
2. 根物件上**删** `SelectStageController`,**挂** `TraceStageController`。
3. Build Settings 把 `Stage_Trace` 放到 **`Stage_Intro` 之后**。
- **验**:选关 → 过场 → 描绘(单手整条 / 双手各描各半,进度独立)→ 描完 → 战斗(正确关卡)。
- 组件上有 `Two Hand Trace` 勾选框:勾上=双手各描一半;取消=单手描整条。

> 建好一个验过一个再建下一个。`Stage_Intro` 没建时选关会退回旧流程;`Stage_Trace` 没建时过场完会退回旧主场景的描绘——**任何一步没做,游戏都还能整条跑通**,不会卡。

## 3. 这一批新增的工具 / 接口

### 运行时脚本
- **`Assets/Scripts/Stages/IntroStageController.cs`** — 过场场景控制器(悬浮漂浮素材 + 入关视频合一)。已改成**手动往前走**。过场完按守卫进 `Stage_Trace` 或退回旧描绘。
- **`Assets/Scripts/Stages/TraceStageController.cs`**(新)— 描绘场景控制器。搬自旧 `ShowTrace/UpdateTrace/CompleteTrace/BuildTracePath`,单手 + 双手各描各半,完成后进战斗。
- **`Assets/Scripts/Stages/SelectStageController.cs`** — 选关确认带守卫:`Stage_Intro` 在 Build 就走它,否则退回旧流程。

### `LijiangEchoStageKit`(共用基础设施)新增的公共方法
- **`ReadForwardAxis()`** → `float`:读"向前推"的连续量(摇杆 Y + 键盘 W/S/↑/↓,带 0.12 死区)。手动往前走用它。
- **`TryGetHandPointer(stageRoot, bool right, out localPoint, out drawing)`**:取**指定某只手**的射线落点 + 该手扳机是否按住。双手各描各半用它(右手判右半、左手判左半,互不干扰)。
- **`TryGetMousePointer(stageRoot, out localPoint, out drawing)`**:编辑器鼠标落点兜底(无手柄时也能描)。
- 已有的 `TryGetActivePointer`(单手活动指针,自带鼠标兜底)供单手描绘复用。

> 用这些做交互前,每帧先调一次 `UpdateControllerInput(stageRoot)`(刷新手柄缓存)。`TraceStageController.Update` 已经这么做了。
